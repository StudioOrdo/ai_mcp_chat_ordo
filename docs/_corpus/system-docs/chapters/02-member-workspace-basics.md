# Member Workspace Basics

A member uses Ordo as a personal operating workspace.

## What This Role Can See

- Their own conversations, files, and operation cards.
- Member-level help for basic workspace use.
- Operation status, buttons, artifacts, and evidence for work they are allowed to see.

## What This Role Can Do

- Start or continue a conversation.
- Add files when the work needs source material.
- Ask for media, documents, or operational help.
- Use visible operation cards when work becomes durable.
- Review results before acting on important changes.

## What This Role Cannot Do

- View staff or admin system documentation.
- Run appliance backups, restores, provider changes, tool governance, or release actions.
- See other users' private operations unless a staff/admin workflow explicitly grants access.
- Execute dangerous work by typing magic phrases into chat.

## When To Expose An Operation Card

Expose an operation card when a member request becomes durable work: media generation, multi-step content work, file-producing tasks, onboarding, help, or any request that can fail asynchronously. The primary next action should be a real button.

## When To Ask A Clarifying Question

Ask a clarifying question when the member asks for broad work but has not provided the target, source material, format, deadline, or approval boundary. Do not create an irreversible operation from vague intent.

## Evidence To Inspect

Inspect the current operation card, operation events, artifacts, uploaded files, and role-visible handbook sections before summarizing progress. If state is missing or blocked, say what evidence is missing.

The assistant should make the next step obvious and avoid exposing staff or admin-only controls.
