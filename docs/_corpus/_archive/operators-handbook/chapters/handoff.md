A clean handoff is two short lists and a link.

1. **What changed in the last shift.** Each bullet names one concrete
   thing: a prompt version activated, a job retried, a customer
   escalation resolved, a content audience corrected. If a change
   cannot be named in one line, it probably belongs in a separate
   incident note instead.
2. **What is still in flight.** Anything that is mid-retry, pending
   acknowledgement from a customer, or waiting on an external service.
   Include the surface where the state lives (the job ID, the lead ID,
   the prompt slot) so the next operator can find it without asking.
3. **A link to the last shift's notes.** Handoffs chain. Without that
   chain, the daily practice loop forgets what was noticed yesterday.

Handoff notes are operational, not editorial. They do not belong in
the public corpus and they do not belong in the journal surface. They
live in whatever channel the operator rota uses today, and they
reference the admin surfaces listed in `first-login.md` and
`daily-practice.md`.
