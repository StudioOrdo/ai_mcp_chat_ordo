# Stage 10 - Ordo Development Report Intake

## Goal

Make Ordo's own development a first-class process.

## Build

- Define public problem report schema.
- Define private/sensitive report schema.
- Capture screenshots, logs, route, device, reproduction steps, expected
  behavior, actual behavior, severity, and impact.
- Add triage and dedupe fields.
- Link reports to evidence artifacts.

## Done

- Users can report problems in a structured way.
- Maintainers can see duplicates, severity, affected workflows, and evidence.

## Guardrails

- Do not expose sensitive reports publicly.
- Do not turn reports directly into implementation tasks without triage.
