# North Star

## Claim

Ordo should become the continuous administrative assistant for solopreneurs.

The conversation thread is the product surface.

Capabilities, memory, policy, and execution paths operate behind that thread.

The operator should not need to think in tools, queues, or runtimes.

## Product Shape

The user runs the business through one continuous thread.

When a request needs heavy execution, Ordo routes it to factory/deferred paths
and returns status and outputs to the same thread.

Examples:

- turn raw expertise into a scrollytelling article with audio, charts, graphs,
  and shorts
- turn QR traffic into attributed leads, consultations, deals, delivery, and
  feedback
- turn Ordo problem reports into QA reports, specs, work orders, fixes,
  verification, releases, and follow-up

## Platform Loop

The common platform loop is:

```text
intent or report
-> context and evidence
-> decision and plan
-> execution target and stage runs
-> artifacts and events
-> QA gates
-> revision and release
-> follow-up and learning
```

The loop must remain visible. Operators need to know what is running, what is
blocked, what evidence exists, and what next action is recommended.

## What Makes Ordo Different

Most AI tools optimize generation. Ordo optimizes governed execution.

The scarce resources are not text, images, or code. The scarce resources are:

- judgment
- evidence quality
- QA
- trust
- workflow discipline
- release confidence

Ordo should make these scarce resources operationally usable in daily work.

## Economic Shape

The platform should preserve static-hosting simplicity while supporting metered
compute where value is created:

- base hosting and low traffic operations
- optional BYOK model usage
- metered storage and server-side processing
- browser-side WASM execution where possible
