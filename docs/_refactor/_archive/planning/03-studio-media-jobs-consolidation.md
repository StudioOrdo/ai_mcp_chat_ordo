# Spec 03: Studio, Media, Jobs, And Work Consolidation

Status: Draft spec

Evidence date: 2026-05-05

## Problem

Media is currently split between Studio and `My media`.

The product kernel says media is work Ordo produced or stores under governance.
That means the regular owner should inspect media in Studio, alongside the job,
workflow, conversation, content, campaign, or offer that created or used it.

More broadly, Studio is the production surface for anything Ordo makes:

- audio,
- images,
- video,
- charts and graphs,
- scripts,
- articles/content,
- offer drafts or offer assets,
- workflows,
- campaigns,
- backups only when surfaced as governed system work.

The current dedicated media page has useful preview and retention logic, but it
should not be a primary account menu item.

## Current Useful Functionality

Keep and reuse:

- Studio object projection across workflows, jobs, media assets, content, and
  campaigns.
- Studio second-column object list and filters.
- Media preview for image, audio, video, chart, graph, and document.
- Media summary/quota/retention metadata.
- Delete eligibility for unattached media.
- Job/workflow/source refs and provenance refs on Ordo cards.

## Target UX

### Studio Base Route

`/studio` shows Production Brief:

- what Ordo produced recently,
- what needs review,
- what is in motion,
- which assets/content/campaigns matter,
- suggested next action.

Second column:

- Overview compact summary,
- search Studio,
- filter icon/sheet,
- object list with media/workflow/job/content/campaign rows.

The second column is where objects live. The base main pane explains the
production brief. Selecting an object opens that one object in the main pane.
Studio should not show global production totals above every selected media
asset or workflow.

### Selected Media Route

`/studio?kind=media_asset&object=...` shows exactly one media asset detail.

It should include:

- media title/file name,
- media type and visibility/retention state,
- preview/player,
- created at,
- size/duration/dimensions where available,
- generated/uploaded/source label,
- attached conversation/workflow/job links,
- provenance/evidence trail,
- safe delete only if unattached and allowed.

It should not include:

- global governed asset totals at the top,
- quota cards above every selected asset,
- raw job ids as primary copy,
- account-level storage management as the main point.

### Selected Workflow/Job Route

Selected work object shows:

- purpose,
- status,
- progress,
- outputs,
- related media,
- related conversation,
- provenance/history,
- owner-safe action.

Raw job detail belongs in admin/system/jobs or a collapsible admin diagnostic
lens, not primary Studio copy.

### Work Provenance Contract

Every Studio object should expose provenance appropriate to its type:

- request/conversation that created it,
- workflow or job that generated it,
- inputs and source objects,
- generated artifacts,
- QA/review events,
- publish/share events,
- related people/offers/content/campaigns.

Owner-facing provenance uses product language:

- `Created from conversation`,
- `Generated by workflow`,
- `Used in campaign`,
- `Published to feed`,
- `Ready for review`.

Admin/system diagnostics can still expose:

- job id,
- provider,
- queue state,
- raw logs,
- operation events.

Those diagnostics must not be the default Studio view.

## Route Policy

- Remove `My media` from account menu.
- Keep `/my/media` temporarily as donor/backward-compatible route.
- Prefer redirect from `/my/media` to `/studio?kind=media_asset` once Studio
  has equivalent preview and retention functionality.
- Do not delete media code until Studio fully consumes the preview/player logic.

## Data Contract

Studio read model should expose enough media detail for selected media:

- id,
- fileName/title,
- mimeType,
- media type,
- source,
- createdAt/updatedAt,
- size,
- duration,
- dimensions,
- previewUrl,
- conversationId,
- generating job/workflow id when known,
- retention state,
- canDelete,
- related cards/source refs/provenance refs.

If existing `UserMediaItem` already has fields, adapt or reuse rather than
duplicating.

## DRY Architecture Recommendation

Extract donor components rather than moving a whole page:

- `MediaPreviewPane`
- `MediaMetadataGrid`
- `MediaRetentionActions`
- `MediaAssetRow`

These should be reusable by:

- Studio selected media detail,
- any admin/system media diagnostics,
- a temporary `/my/media` compatibility route.

## Acceptance Criteria

- Studio second column can filter to Media.
- Studio second column is the normal place to select media, workflows, jobs,
  content, and campaigns.
- Selecting a media item opens a single media detail with player/preview.
- The media detail links to related job/workflow/conversation when available.
- Account menu no longer links to My media.
- `/my/media` is not needed for normal owner operation.
- No global storage totals dominate selected media detail.
- Every selected Studio object includes type-appropriate controls and
  provenance/source links.

## Tests

Positive:

- Studio media item appears in second-column list.
- selecting media renders audio/video/image/chart/graph preview as applicable.
- selected media detail includes related conversation/job/workflow link when
  source data exists.
- unattached media exposes safe delete only when allowed.

Negative:

- selected media detail does not show global quota cards above the asset.
- regular owner Studio detail does not expose raw job log/provider diagnostics.
- account menu does not show My media.

Edge:

- unsupported media falls back to open/download preview.
- missing preview URL shows a quiet unavailable state.
- media without related job still shows source and retention safely.
