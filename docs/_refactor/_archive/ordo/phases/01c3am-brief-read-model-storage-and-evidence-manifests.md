## Goal

Add the durable read-model foundation for section and object briefs.

The first implementation may keep brief text deterministic, but briefs must be
represented as evidence-backed objects with history, limitations, and source
links rather than component-local prose.

## Required Work

Define and implement durable or adapter-backed brief contracts:

```ts
interface SectionBrief {
  id: string;
  sectionId: string;
  objectRef?: { kind: string; id: string; label: string };
  asOf: string;
  status: "fresh" | "stale" | "limited" | "failed";
  bullets: string[];
  recommendedAction: OrdoAction | null;
  evidenceRefs: OrdoSourceRef[];
  limitations: string[];
  version?: number;
  priorBriefId?: string;
}
```

Manifest requirements:

- schema version,
- brief id/version,
- generated at,
- generated by,
- owner/user scope,
- visibility policy,
- included source refs,
- excluded source refs and reasons,
- claims and supporting evidence refs,
- limitations,
- model/executor metadata if generated,
- warnings.

Implementation rules:

- Every claim has evidence or a limitation.
- Private/admin evidence cannot leak into public-safe briefs.
- Failed/stale briefs do not erase the prior brief.
- Base section routes consume brief objects.

Implemented scope:

- Added shared brief contracts in `src/core/entities/brief.ts`.
- Added durable tables:
  - `brief_read_models`
  - `brief_events`
- Added `BriefReadModelDataMapper` for validated save/read/history/event
  access.
- Registered `getBriefReadModelDataMapper()` in the repository factory.
- Updated `GovernanceSectionFrame` to consume the shared `SectionBrief` type and
  render evidence links, as-of state, status, and limitations.
- Kept deterministic section loaders in place. This phase establishes durable
  storage and validation so later executor phases can write/read the same
  contract without changing owner UI.

## Tests

Positive:

- stored/adapter brief renders with as-of timestamp and evidence links.
- updated brief creates history/trail evidence.
- section brief reflects source evidence changes.
- limitations render when evidence is incomplete.

Negative:

- brief cannot include ungrounded fake metrics.
- owner brief does not expose raw job/provider/log details.
- public-safe brief cannot include private evidence.

Edge:

- stale brief renders stale marker or refresh action.
- failed brief keeps prior brief.
- missing source evidence produces limited state.

## Non-Goals

- Do not implement background execution in this phase.
- Do not require LLM generation.
- Do not migrate all object brief types if the storage/read-model seam is not
  stable.
