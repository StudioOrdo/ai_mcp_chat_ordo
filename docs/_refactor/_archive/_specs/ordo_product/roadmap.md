# Ordo Product Roadmap

## Principle
Do not add lots of new tools first. Make the current system product-shaped by
classification, context, read models, and UI surfaces.

## Phase Sequence
1. Product foundation and catalog prompt exposure.
2. Role/context tool surface pruning.
3. Theme/accessibility and profile control plane.
4. Affiliate/referral product surface.
5. Customer media and asset experience.
6. Job operations and attention/inbox model.
7. Work-order/content/factory simplification.
8. Staff/admin operations separation.
9. Founder coach and daily briefing.
10. Research/write/QA/store-in-library workflow planning.

## Dependencies
- Asset catalog completion supports media, workspace restore, and library
  workflows.
- Search index execution supports Knowledge Office and library production.
- MCP registry cutover supports governed admin/operations exports.
- Storage accounting supports media/customer/admin storage UX.
- Work-order summary read model supports Product Factory and Content Studio.

## Success Criteria
By the end of this package:
- Default prompt exposure is smaller and context-aware.
- Authenticated users get a clean paid customer/student experience.
- Theme/accessibility remains easy and universal.
- Affiliate QR/performance is clear for users and staff/admin.
- Staff/admin operations are separated from customer capabilities.
- Jobs and work orders are visible through read models, not raw internals.
- Notifications become an attention ledger/inbox.
- Ordo product model is coherent: chief of staff over business units.
