# Contributing To Ordo

Thanks for helping.

Ordo is still in active development. The best help right now is clear feedback:
bugs, broken links, confusing docs, screenshots, failed commands, and places
where the project says more than the code can prove.

## Start With An Issue

Please open an issue before opening a code pull request.

Good issues are simple:

1. What did you try?
2. What did you expect?
3. What happened instead?
4. Where did it happen?
5. Can you add a screenshot, log, command output, or link?

You do not need to write a perfect report. You do need to make it concrete.

## Which Issue To Use

- **Alpha Feedback**: feedback from using, testing, or watching Ordo.
- **Bug Report**: something broke.
- **QA Report**: a detailed test or review finding.
- **Docs Feedback**: broken, stale, confusing, or overblown docs.
- **Runtime Integrity Regression**: the app says or shows something that does not
  match its data or rules.

## Code Changes

Code changes are welcome when they are tied to a clear issue and a small scope.

For now, large drive-by rewrites are hard to review because the app is still
being shaped. A good code pull request should include:

- the issue it fixes;
- what changed;
- tests or commands run;
- screenshots when the UI changed;
- risks or follow-up work.

## Conduct

Be direct, specific, and respectful.

The goal is simple: make the product clearer, sturdier, and easier to trust.
